# Register an Animal to LIS: endpoint mapping summary

This summarises the **six evaluated routes**. “Routine” means a straightforward field or shape transformation **after** identity and business semantics are confirmed; it does not mean the whole endpoint can be implemented from LIS alone. The route-level assessments below use the Register an Animal repository and the supplied LIS OpenAPI specification. The individual endpoint evaluations contain field inventories, error responses and outstanding questions.

| Register an Animal endpoint | LIS counterpart and outcome | Main issue / work needed |
|---|---|---|
| `GET /v1/holdings/{county}/{parish}/{holding}` | **No equivalent.** Holding details come from KRDS, not LIS. | LIS does not provide a holding-details operation or the required holding address, keeper, marks, dates and associations. Retain an authoritative holding source or define a new contract. |
| `GET /v1/holdings` | **No equivalent.** Generic holding search comes from KRDS. | LIS animal search cannot search holdings by free text or return holding summaries and their paging metadata. Retain a holding-search source or define a new contract. |
| `GET /v1/holdings/{county}/{parish}/{holding}/cattle` | **Related LIS operation: `GET /animals`; partial field mapping only.** | CPH to `siteIdentifier` and `species=cattle` need agreement. Flattening animal identifier, sex and breed is relatively routine **if semantics match**, but LIS list results lack birth/arrival dates, local processing status and per-animal errors. LIS paging, missing filters and local-record merging prevent a direct full response translation. |
| `GET /v1/holdings/{cph}/cattle` | **Related LIS operation: `GET /animals`; same partial mapping.** | Shares the cattle-list gaps above. Additionally, the single CPH path value is unescaped, not joined from three segments; accepted spelling/encoding and equivalence to LIS `siteIdentifier` must be confirmed. A hyphenated route value is not proof of a match to slash-separated stored CPHs. |
| `GET /v1/holdings/{county}/{parish}/{holding}/bundles` | **No equivalent.** Lists locally stored submissions. | LIS individual-animal fields are related but cannot reconstruct bundle IDs, membership, submitted values, statuses, timestamps or per-animal processing errors. Keep local history or define a bundle-list contract. |
| `GET /v1/holdings/{cph}/bundles` | **No equivalent.** Same local submission lookup. | Shares the bundles gap above. This route passes one unescaped CPH value to an exact stored-CPH match; hyphenated and slash-separated spellings must not be assumed interchangeable. |

**Overall:** None of the six routes has a confirmed, complete LIS-only mapping. The two cattle-list routes are the closest match and contain some **potentially routine field transformations**, but need additional data and agreed rules to preserve the Register an Animal response. Holding and bundle routes need their existing authoritative data sources or new LIS capabilities. Authentication, correlation headers and error-body/status translation also need treatment when introducing LIS; similar status codes or field names alone do not establish equivalence.
