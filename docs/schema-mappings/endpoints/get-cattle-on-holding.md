# GET /v1/holdings/{county}/{parish}/{holding}/cattle: API schema mapping

This evaluates Register an Animal's cattle-on-holding request and response against LIS `GET /animals`. The Register an Animal repository defines its behavior and DTOs; the LIS API contract defines the LIS request and response. It follows the object, endpoint, request, response, and breaking-change layout of the other endpoint evaluations.

**Assessment:** These are both *animal-list* operations, unlike the holdings-search endpoints, but they are **not directly equivalent**. A **candidate** mapping is a plausible field correspondence that still needs an agreed rule or evidence. **N/A** means no source field in the LIS animal-list response; do not synthesize a value or imply that an unrelated endpoint supplies it.

## Object Mapping

| Register animal/cattle API object | LIS API object | Notes |
|---|---|---|
| `CattleFilter` plus required `county`, `parish`, `holding` path segments | `GET /animals` query parameters | The CPH may correspond to LIS `siteIdentifier` if its format/semantics are confirmed. LIS also requires `species`; it offers no equivalent ear-tag, breed, or sex list filters. |
| `CattleResponse[]` | `GET /animals` `200` object containing `count` and `values` of `AnimalSummary` | Requires extraction of `values`, aggregation of pages, and transformation of animal fields. It cannot directly supply all Cattle fields. |
| `CattleErrorResponse` within each animal | N/A | LIS `AnimalSummary` has no per-animal processing-error list; LIS HTTP `Errors[]` is not equivalent. |
| `ProblemDetails` for endpoint failures | LIS `Errors[]` for some failure statuses | Different body shape, media type, status semantics, and error ownership. |

## Endpoint Mapping

| Register an animal/cattle API endpoint | LIS API endpoint | Equivalence / transformation |
|---|---|---|
| `GET /v1/holdings/{county}/{parish}/{holding}/cattle?EarTag=&Breed=&Sex=` | **Related, not equivalent:** `GET /animals?species=cattle&siteIdentifier=...` | Both list animals associated with a location. LIS requires a site identifier and species; Register an Animal returns CADS cattle **plus local submission records**, applies optional filters after merging, and returns an unpaged array. LIS returns paged animal summaries with fewer fields and different state semantics. |

The Register an Animal service calls CADS `api/v1/bovine/animals?CPH=...` (reading successive CADS pages), optionally supplements CADS data from a temporary patch, and merges locally stored submitted/error records. That is how its present response is assembled; LIS does **not** document those sources or their merge rules. The `/v1/holdings/{cph}/cattle` variant uses the same service but is a separate route; this evaluation is for the three-segment endpoint only. LIS paths are relative to its server's `/v1` prefix.

## Request Mapping

There is **no request body**. Register an Animal's three required path strings are joined as `county/parish/holding`; unlike the separate holding-details operation, this route does not itself apply a 2/3/4-digit segment validator. Query parameters bind to `CattleFilter` and are optional. If supplied, `EarTag` matches a substring after removing spaces and ignoring case; `Breed` matches a breed code, name, or breed string by case-insensitive equality; `Sex` matches by case-insensitive equality after trimming. All three filters are applied **after** CADS and local records are combined.

**Headers (not JSON fields):** Register an Animal requires service-to-service API-key authentication and a single nonblank `x-cdp-request-id` correlation header on versioned routes. LIS uses subscription-key and access-token security; its `200` also documents `LI-Request-Id` and `LI-Correlation-Id` headers. Credential provisioning and correlation propagation need separate policies, not a field rename.

## Response Mapping

### `200 OK` — array of `CattleResponse`

The Register an Animal endpoint returns **one unpaged JSON array**, including CADS records and eligible local submission/error records; an empty list is possible. A CADS match is enhanced with the local status and errors, and a local-only record is added. LIS returns **an object** containing `count` and `values` with `AnimalSummary` items. The LIS schema gives `values` an `items` definition but omits its `type: array`; its intended collection shape needs confirmation. Its animal list does not include dates, local submission state, or per-animal errors. `Nullable` for Register an Animal describes C# DTO types, not guaranteed runtime non-null values; `Required` is not explicitly established by DTO declarations. LIS `AnimalSummary.animal` and `breed` are not marked required at the top level, so nested field availability must be checked before any transformation.

**Unmapped LIS fields:** `values[].animal.species`, `values[].animal.name`, `values[].animal.state`, and `values[].breed.crossBreed` have no directly equivalent required Cattle list fields. Species could be checked against cattle-only assumptions, but must not overwrite `status`; animal name and cross-breed information would be omitted unless the consumer contract changes. The LIS `count` describes its animal result, **not necessarily** the number of Cattle items after local merging and filtering.

### `401 Unauthorized` — Register an Animal `ProblemDetails`

The Register an Animal API-key rejection produces a `401` problem response with `type`, `title`, `status`, and `detail` explicitly set. LIS `GET /animals` documents `403 Forbidden` with an `application/json` `Errors[]` body (1–1000 LIS `ProblemDetails` items). Similar field names below are **schema-level comparisons**, not proof that a downstream `403` should become an upstream `401`.

### `404 Not Found` — Register an Animal `ProblemDetails`

A CADS holding-not-found error becomes a local `404` problem response with `type`, `title`, `status`, `detail`, and `instance` set by the exception handler. LIS `GET /animals` also documents `404`, but the LIS OAS does not establish whether it means a missing *site*, no animals, or another condition. A normal `200` empty list must **not** be translated into a `404` without an agreed rule. LIS `404` uses `Errors[]`, requiring an array-to-object transformation if semantics are confirmed.

### `400 Bad Request`, `500 Internal Server Error`, `503 Service Unavailable`

A missing/nonblank-required `x-cdp-request-id` returns local `400 ProblemDetails` with `code: missing_header`; argument or other request errors can also yield `400`. The exception handler maps service unavailability to `503` and unhandled errors to `500`, adding `traceId` and `correlationId` extensions. LIS animal search documents `500` and `503` as `application/json` `Errors[]` (not the same shape); it does **not** document a `400` response on `GET /animals`. Local authentication or correlation errors should not be attributed to LIS.

## Breaking changes and decisions

| Finding | Status / impact | Decision needed |
|---|---|---|
| `siteIdentifier` and `species=cattle` look suitable for locating cattle, but site identity/format and filter semantics are not verified. | **Plausible request-level mapping, not a proven equivalent.** | Confirm LIS's site identifier matches the Register an Animal CPH and agree cattle-only species behavior. |
| LIS has no `EarTag`, `Breed`, or `Sex` list query filters; Register an Animal applies substring/equality filters after merging CADS and local records. | **Missing filter capabilities**; filtering a single page would change results. | Define full-page retrieval and local post-filtering if LIS is used, including error and completion behavior. |
| LIS returns paged `AnimalSummary` items in an object, whereas Register an Animal returns an unpaged array of CADS and local animals. | **Cardinality/shape and data-source gap**; a rename cannot reproduce local-only animals. | Confirm page traversal guarantees, local-submission availability, and how records are merged/deduplicated. |
| Birth date, date on CPH, CADS/submission status, and per-animal processing errors are not available in the LIS animal-list response. | **Missing attributes and incompatible status values**; prevents full direct response translation. | Identify authoritative supplementary sources/operations or agree explicit contract changes; do not fabricate dates/status/errors. |
| LIS breed is an optional object and sex is an enum; Cattle uses nullable strings and may include locally stored values. | **Structural nesting, datatype/allowed-value, and nullability differences.** | Confirm code/name semantics, casing, out-of-enum handling, and source for local-only cattle. |
| Error responses have different media types/body cardinality and authorization semantics (`401` versus LIS `403`). | **Potentially breaking error/status translation.** | Define status-specific policies; distinguish locally generated from downstream failures. |

**Result:** LIS `GET /animals` is the appropriate **animal-list operation to evaluate** against this Register an Animal route, but its documented list contract is **not sufficient for complete direct translation**. The CPH/site input and some animal identity, sex, and breed fields have plausible mappings; the missing dates, local statuses/errors, filters, and page/merge rules must be resolved before a LIS-backed facade can preserve the Register an Animal output.
